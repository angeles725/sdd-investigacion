### zip-readers (#2416)

| Tool | Description |
|---|---|
| `rsdd formats zip-metadata --input <zip> --output <new-dir> --manifest-cli <analysis_manifest.py> [caps]` / `rsdd formats zip-stored --input <zip> --output <new-dir> --manifest-cli <analysis_manifest.py> [caps]` | Go port (kit issue #2416, epic #2270) of `zip_metadata.py` and `zip_stored.py`; the registry rows `zip-metadata.sh` / `zip-stored.sh` above and their contracts ([`zip-metadata.v1`](../zip-metadata.v1.md), [`zip-stored.v1`](../zip-stored.v1.md)) still describe the behaviour. The two `.sh` entry points are compatibility shims that hand over to `lib/rsdd-exec.sh` and pass the hidden `--manifest-cli` (the analysis-manifest tool is still Python until U6.2); they are removed in phase 8. The legacy `zip_metadata.py` / `zip_stored.py` are no longer called by anything: frozen copies under `rsdd/internal/formats/testdata/zip/legacy/` stay only as the parity oracle of the Go tests (`internal/formats`, `testdata/zip/parity_driver.py`) until phase 8. The parser is a reusable reader (`ReadZipDirectory`, `ReadLocalHeader`, `OpenMember`, `ReadMember` in `internal/formats/zipread.go`: central directory, local header, STORED and DEFLATE members with size bounds and CRC-32 check). Intended differences from the Python tools are listed in each contract under "Intended differences from the Python tool": Go flag parsing (full flag names only; `--metadata-parser` removed from zip-stored), the analysis manifest names the `rsdd` binary as launcher with no tool artifacts, integer caps beyond int64 are a usage error, OS error wording, `DEGRADED:` prefix on zip-stored's exit-3 line. |
