### kit-flake-hunt

| Tool | Interface and contract |
|---|---|
| `maint/kit-flake-hunt.sh [--repo DIR] [--runs K] [--load N] [--load-timeout S] [--suite-timeout S] [--suites FILE \| --suite PATH ...] [--tier core\|all] [--prove-teeth] [--out DIR] [--file-issues[=apply]]` | Load-flake hunter (kit issue #2209; incident #2197): runs the selected suites K times (default 3) under N `timeout`-bounded busy loops (default nproc/2; each worker is also killed by PID on exit/INT/TERM, never by name; default `--load-timeout` = runs x suites x suite-timeout + 300 s, and a worker found dead before a suite is `degraded: load expired at run R`, exit 2) and records `<run>\t<suite>\t<PASS\|FAIL\|SKIP\|TIMEOUT>\t<first FAIL line>` in `<out>/results.tsv` (default `${XDG_STATE_HOME:-$HOME/.local/state}/research-sdd/flake-hunt/<timestamp>`). `--out` is resolved and judged before anything is created: the repo itself, anything inside it (including via `.`, `..` or a symlink) and an existing non-empty directory are refused, and the script never removes a directory it did not create. A suite PASSes like in `run-all.sh` (exit 0 plus a `== N passed · M failed ==` line with M=0 and N>0); each suite gets its own TMPDIR under `<out>/tmp`, removed afterwards; `*.test.mjs` suites run under `node` (probed only when one is selected) without `--prove-teeth`. Reports `flaky: <suite> failed X/K — <line>` for a suite that failed in some runs but not all, `broken: <suite> failed K/K — <line>` for one that failed in every run (a defect, not a flake; `--runs 1` cannot tell them apart), and `Flake hunt: runs=K suites=M load=N flaky=F broken=B stable=S skipped=P`. A TIMEOUT counts as a failure; a clean exit with a `SKIP:` line is a skip, and a hunt where every suite skipped is degraded (`nothing measured`). Suite selection defaults to `run-all.sh --list-suites`; `--tier core` falls back to the full list with a `note:` line when the runner rejects `--tier`. `--repo` replays an old tree (the pre-fix commit of an incident) with the current script. `--file-issues` prints the exact `gh issue create` / `gh issue comment` it WOULD run per flaky suite (dry; for flaky and broken suites; deduped against open issues whose title starts with `flake: <suite file> `, `gh` run inside `--repo`, label `type:bug`); only `--file-issues=apply` runs it, and a failed search or missing `gh` files nothing. Exit 0 clean · 1 at least one flaky or broken suite · 2 degraded or bad usage (missing `timeout`/`nproc`/`node`, no `run-all.sh`, empty suite list, unreadable list, refused `--out`, expired load, nothing measured, failed issue search). Suites see `FLAKE_HUNT_RUN`, `FLAKE_HUNT_SUITE`, `FLAKE_HUNT_OUT`. Companion suite: `tests/kit-flake-hunt.test.sh`. |
