### kit-flake-hunt

| Tool | Interface and contract |
|---|---|
| `rsdd maint flake-hunt` (shim `maint/kit-flake-hunt.sh [--repo DIR] [--runs K] [--load N] [--load-timeout S] [--suite-timeout S] [--suites FILE \| --suite PATH ...] [--tier core\|all] [--prove-teeth] [--out DIR] [--evidence-url URL] [--file-issues[=apply]]`) | Go port (kit issue #2209, Go port of the maint batch), package `rsdd/internal/maint/flakehunt` (args, validate, suites, outdir, load, signals, child, hunt, verdict, report, issues, quote: one responsibility each; the help text is embedded). Pinned by a differential test against the frozen legacy script under `internal/maint/flakehunt/testdata/legacy` (stdout, stderr, exit code and every file the run leaves, over 98 scenarios), by one Go test per `.github/workflows/flake-hunt.yml` invocation shape (the nightly shard step, every dispatch input, the documented cron line, the flags the workflow file passes) and by `tests/kit-flake-hunt.test.sh` against the shim. The shim passes its own checkout as `--repo` first, so a caller's `--repo` still wins. Load-flake hunter (kit issue #2209; incident #2197): runs the selected suites K times (default 3) under N `timeout`-bounded busy loops (default nproc/2; each worker is also killed by PID on exit/INT/TERM, never by name; default `--load-timeout` = runs x suites x suite-timeout + 300 s, and a worker found dead before a suite is `degraded: load expired at run R`, exit 2) and records `<run>\t<suite>\t<PASS\|FAIL\|SKIP\|TIMEOUT>\t<first FAIL line>` in `<out>/results.tsv` (default `${XDG_STATE_HOME:-$HOME/.local/state}/research-sdd/flake-hunt/<timestamp>`). `--out` is resolved and judged before anything is created: the repo itself, anything inside it (including via `.`, `..` or a symlink) and an existing non-empty directory are refused, and the script never removes a directory it did not create. A suite PASSes like in `run-all.sh` (exit 0 plus a `== N passed · M failed ==` line with M=0 and N>0); each suite gets its own TMPDIR under `<out>/tmp`, removed afterwards; `*.test.mjs` suites run under `node` (probed only when one is selected) without `--prove-teeth`. Reports `flaky: <suite> failed X/K — <line>` for a suite that failed in some runs but not all, `broken: <suite> failed K/K — <line>` for one that failed in every run (a defect, not a flake; `--runs 1` cannot tell them apart), and `Flake hunt: runs=K suites=M load=N flaky=F broken=B stable=S skipped=P`. A TIMEOUT counts as a failure; a clean exit with a `SKIP:` line is a skip, and a hunt where every suite skipped is degraded (`nothing measured`). Suite selection defaults to `run-all.sh --list-suites`; `--tier core` falls back to the full list with a `note:` line when the runner rejects `--tier`. `--repo` replays an old tree (the pre-fix commit of an incident) with the current script. `--file-issues` prints the exact `gh issue create` / `gh issue comment` it WOULD run per flaky suite (dry; for flaky and broken suites; deduped against open issues whose title starts with `flake: <suite file> `, `gh` run inside `--repo`, label `type:bug`); only `--file-issues=apply` runs it, and a failed search or missing `gh` files nothing. Exit 0 clean · 1 at least one flaky or broken suite · 2 degraded or bad usage (missing `timeout`/`nproc`/`node`, no `run-all.sh`, empty suite list, unreadable list, refused `--out`, expired load, nothing measured, failed issue search). Suites see `FLAKE_HUNT_RUN`, `FLAKE_HUNT_SUITE`, `FLAKE_HUNT_OUT`. Companion suite: `tests/kit-flake-hunt.test.sh`. |

CI contract (`.github/workflows/flake-hunt.yml`, kit issue #2209 part 2; unchanged by the port): the shard step passes `--runs --prove-teeth --load --suites --out --evidence-url --file-issues=apply` with `GH_TOKEN` set for that step only; the workflow reads the exit code (0 clean, 1 flaky or broken, 2 degraded), uploads the whole `--out` directory (`results.tsv`, `logs/<run>-<n>.log`, `issue-<suite file>.md`) and relies on the issue title `flake: <suite file> failed X/K under CPU load` (an open issue whose title starts with `flake: <suite file> ` is commented on, never duplicated). Each shape is a Go test in `workflow_test.go`; TERM and INT stop the workers and the running suite by process group and exit 143 and 130.

Intended divergences from the bash tool (each pinned by a Go test in `divergence_test.go` or `load_test.go`; everything else is byte-identical, including stdout, stderr and every output file):

| Divergence | Why |
|---|---|
| `-h` / `--help` prints the full help on stdout (the bash printed one usage line on stderr); a flag missing its value still prints that usage line on stderr, exit 2 | the help is embedded text now, like every other ported command |
| numbers are decimal and of any length: `--runs 02` is 2 (the bash read it as octal inside its arithmetic), `--runs 99999999999999999999` is one usage line (the bash also leaked `[: integer expression expected`), and a summary line with 20-digit counts is judged as digits | the bash overflowed or misread them |
| a trailing slash on `--out` is dropped from the resolved path | the bash kept it in the `Results:` line |
| `--out` that cannot be created is one typed line `degraded: kit-flake-hunt: cannot create output directory <dir>` | the bash also leaked `mkdir`'s own message |
| without `--repo` the hunt takes the kit checkout around the working directory (nearest ancestor holding `research-sdd/toolbelt`, else the directory itself); the shim passes its own checkout first | the Go command cannot see where the shim lives |
| a TERM or INT also removes the TMPDIR of the suite it stopped | the bash left `<out>/tmp/<run>-<n>` behind |
| `awk`, `date`, `mktemp`, `grep`, `sed` and `sort` are no longer dependencies; only `bash`, `timeout` and `nproc` are probed | the log judging, the timestamp and the directory handling are Go now |
