### verify-corrections (#2625)

| Tool | Description |
|---|---|
| `rsdd verify corrections <target-dir>` | Go port (kit issue #2625, epic #2270) of `verify-corrections.sh`; the registry row `verify-corrections.sh <target-dir>` above still describes what it checks and prints, and its exit contract holds: 0 every declared correction is reciprocated (or none), 1 a one-directional correction, 2 bad arguments or no block files. `verify-corrections.sh` is a compatibility shim that hands over to `lib/rsdd-exec.sh` (the shim is removed in phase 8); the report is produced by the binary, byte for byte as the script printed it, and `research-sdd-archive.sh` (gate AR-VCORR) reads it unchanged. The block-file discriminator is the single `internal/core/kit` one (`FilterBlockFiles`, depth <= 3, no `*.template.md`, no `.git`), no second copy. The frozen script and `lib/block-files.sh` (pinned by `SHA256SUMS`) are the parity oracle of the Go differential tests (`research-sdd/rsdd/internal/verify/corrections/testdata/legacy`): the real-corpus fixtures and seeded random corpora must print the same stdout, stderr and exit code. Intended differences, each pinned by a Go test (`TestLegacyDefectsFixed`, `TestReportOrderIsBytewise`, `TestQualifiers`, `TestVocabulary`): (1) a block number beyond 64 bits is compared as digits (the script's `$((10#N))` wrapped or aborted the run mid-report); (2) a target block holding a NUL byte is read as text (the script's `grep` answered "Binary file matches", so a present backlink read as missing and produced a false FAIL); (3) one target written twice in one file (`[Block 8]` and `[Block 008]`) is one finding, not two identical lines; (4) a trailing `_` after the correcting block's number no longer defeats the match (`_corrected in B33_`, the markdown-italics shape the vocabulary comment promises, was rejected because `_` counted as word text); (5) the report order is bytewise (the script's `sort` followed the caller's locale) and a focus slug matching several block prefixes that differ only by case resolves to the byte-smallest one (the script took bash's arbitrary hash order); (6) the word-boundary and case rules are locale-independent: ASCII case folding for the vocabulary and Unicode letters, digits and `_` as word text for the block reference (the script ran the two greps under `LC_ALL=C` and the caller's locale respectively); (7) no `awk`, `grep`, `sed` or `sort` is run, so the `degraded: awk not found` guard, the `cannot find helper` / `failed to define block_file_filter` guards and the mawk/gawk differences do not exist (a block file that cannot be read is still the typed `degraded: extractor (awk) failed on <file>` line and exit 1, kept verbatim so callers that match it keep working). |
