### squashfs-qnx6 (#2417)

| Tool | Description |
|---|---|
| `rsdd formats squashfs-extract --input <file> --output <new-out-dir> [--manifest-cli <ignored>] [--max-input-bytes N] [--max-extracted-bytes N] [--max-entries N] [--timeout-seconds N]` / `rsdd formats qnx6-read list\|extract ...` | Go port (kit issue #2417, epic #2270, unit U6.14) of `squashfs_extract.py` and `qnx6_read.py` (`rsdd/internal/formats/squashfs*.go`, `qnx6*.go`). The rows for `squashfs-extract.sh` ([`squashfs-extract.v1`](../squashfs-extract.v1.md)) and `qnx6-read.sh` ([`qnx6-evidence.v1`](../qnx6-evidence.v1.md)) above still describe the contract, unchanged (exit codes, evidence schemas, refusals). Both `.sh` entry points are compatibility shims over `lib/rsdd-exec.sh` (`$RSDD_BIN`, then `<kit>/bin/rsdd`); `squashfs-extract.sh` also hands over the sibling `analysis_manifest.py` as `--manifest-cli`. They are removed in phase 8. The Python files are gone; the frozen scripts live under `rsdd/internal/formats/testdata/{squashfs,qnx6}/legacy/` as the differential oracle of the Go tests. Intended differences (each documented in the two contract documents): a symlink to a directory is refused where it first appears; an unlistable directory is an error, not a silent skip; a stage directory left by another run is never deleted; a FIFO input is refused instead of blocking; the manifest's launcher is the rsdd binary; `qnx6-read` reports a crafted-offset crash as a typed failure. |
