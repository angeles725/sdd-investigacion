### score-loop-transcript (#993)

| Tool | Description |
|---|---|
| `rsdd eval score-loop --corpus <dir> [--transcript <jsonl>] [--base-ref <ref>] [--since <date>] [--until <date>]` | Go port (kit issue #993, epic #2270) of `score-loop-transcript.sh`; the registry row `score-loop-transcript.sh --corpus <dir> ...` above still describes what C1-C4 check and print, and its exit contract holds: 0 scored (findings never fail the run), 1 operational, 2 usage, 3 degraded. `score-loop-transcript.sh` is a compatibility shim that hands over to `lib/rsdd-exec.sh` (the shim is removed in phase 8) and passes its own directory as `--toolbelt <dir>`, where the Go command looks for `research-sdd-status.sh` (still a bash script) after `RSDD_STATUS_SCRIPT`. The code is the domain package `internal/eval/scoreloop`, one file per responsibility: `args`, `config` (every `RSDD_*` override and the regular expressions), `record`/`verdict`/`lastpara`/`timeparse`/`transcript`/`jqfilter` (the transcript reader), `blocks`/`window` (the git window and weighted block commits), `c1`..`c4*` (one file per criterion and its sub-rules), `status` (the `research-sdd-status.sh` integration) and `report`/`run` (rendering and composition). The frozen script (`internal/eval/scoreloop/testdata/legacy/score-loop-transcript.sh`) is the parity oracle: about 340 black-box cases are replayed against recorded goldens (`testdata/golden/cases.json`) and, outside the `nodiff` tag, against the live script. Behaviour is byte-identical except the intended divergences below, each declared on its case (`intended` with a reason, enforced by `parity.Judge`) and mirrored by a golden holding the Go output. Intended differences: (D1) an invalid or under-grouped `RSDD_BLOCK_COMMIT_REGEX`, `RSDD_BLOCK_ID_REGEX`, `RSDD_QUESTION_REGEX` or `RSDD_STOP_TOKEN_REGEX` is an exit-2 usage error naming the variable (bash silently matched nothing, or crashed on an unbound `BASH_REMATCH`, and could report a clean pass); (D2) `jq` is no longer required: the operator-turn and compaction tests run in Go, and `jq` is needed only for an `RSDD_OPERATOR_INPUT_JQ` or `RSDD_COMPACT_JQ` override (a missing `jq` with an override is still the typed `degraded` line); (D3) `base64` is no longer required (the last paragraph needed a round trip through it); (D4) GNU `date -d` is no longer required: timestamps parse in Go (RFC 3339 forms, a space separator, a missing zone read as UTC); (D5) records sort by instant: the bash `sort` was lexical on the timestamp string, so a fraction or a zone offset reordered records; (D6) a non-string `timestamp` is dropped (bash handed jq's text of it to `date -d`, which read a bare number as an hour of today and produced a bogus window); (D7) a leading-zero integer in `RSDD_C4_AFTER_STOP_GRACE` or `RSDD_BLOCK_RANGE_CAP` is decimal (bash arithmetic read `010` as octal 8); (D8) with `git` absent the `degraded` line stands alone: bash also printed a `dirname: command not found` line. Dependency probes are typed: a missing `git` degrades the whole instrument, a missing `jq` degrades only the transcript criteria, and the status script is run with a timeout and an output cap, so a hung or flooding script is a `degraded` C4, never a hang. `lib/rsdd-exec.sh` gives the shim its typed `degraded: rsdd-unavailable` exit 2. |
