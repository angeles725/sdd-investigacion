### research-sdd-status (#2549)

| Tool | Description |
|---|---|
| `rsdd status show <target-dir> [--next\|--sync-state] [--focus <slug>] [--root]` | Go port (kit issue #2549, epic #2270) of `research-sdd-status.sh`, in slices; the script stays authoritative until the last slice makes it an `rsdd_exec` shim. Intended differences from the script (a legacy defect is fixed in Go, pinned by a test, and documented here; byte parity stays where a caller depends on the contract): (1) a state-file listing that fails in `--next` or `--sync-state` is `research-sdd-status: degraded: cannot list the state files under <dir>: <err>` on stderr and exit 1, no verdict, no write, where the script walked whatever list it got; (2) verify-state unavailable (`RSDD_TOOLBELT_DIR` unset, or `verify-state.sh` missing or not executable) is `research-sdd-status: degraded: verify-state unavailable (<reason>)` on stderr and exit 1, no verdict on stdout, where the script printed a STALE `reconcile first` or let the stopped-focus bypass hand out an unverified NEXT; (3) a verify-state killed by a signal is exit 128+signal (137 for SIGKILL), as the shell reports it; (4) a failed temp-file create or rename in `--sync-state` is a typed exit 1 where the script printed mv's error and still claimed `wrote`; (5) a slug or id holding a lone `)` is escaped before `grep -E` (kit finding F8), so it matches literally as GNU grep does. `--next` is whole in Go from slice S5 (the RETRO-DUE `covers_through` derivation, `issues_due_gate`, the terminal clean-check warning); the children it starts are exactly `gh issue list` (one read-only batch prefetch, bounded by `_IDG_RECONCILE_TIMEOUT_SECS`, default 15 s, `--limit` from `_IDG_BATCH_LIMIT`), this binary as `rsdd retro reconcile [--toolbelt <dir>] [--issues-cache <file>] <retro>` (one probe per unsettled retro, one re-verify per retro the batch calls untracked; no bash and no `reconcile-issues.sh` shim in between) and `bash <toolbelt>/clean-check.sh --target <dir>` (only without `RSDD_STATUS_NO_CLEAN_CHECK=1`); no git subcommand and no gh write ever runs. Further intended differences, all from slice S5: (6) the bound of every child is `core/proc`'s, not `timeout(1)`/`gtimeout`, so the script's "no timeout binary" states and the `_IDG_TIMEOUT_BIN` test hook do not exist, an unusable `_IDG_RECONCILE_TIMEOUT_SECS` (the script made `timeout` fail every call with exit 125) is the default 15 s, and clean-check's two streams are read stdout then stderr instead of interleaved by `2>&1`; (7) a probe's stderr and the batch are captured in memory, so the script's `mktemp failed for retro enumeration`, `... for retro enumeration stderr`, `... cannot capture reconcile stderr`, awk-count and sort-failure warnings cannot occur, while `mktemp failed for issue-cache` (the batch cache file) stays and no longer makes the script skip every probe; (8) the retro listing is in byte order whatever the locale (the gate's `sort` followed the caller's locale, the derivation's `LC_ALL=C`), so the first retro that is untracked is the same on every machine; (9) the block-id digits of the newest-block scan are the second-to-last regex group, not `BASH_REMATCH[2]`, so a focus prefix that holds its own `( )` group no longer feeds a prefix fragment into the arithmetic; (10) the script's `lib/retro-status.sh not found` warnings are gone with the sourced helper (`core/retrogrammar` reads the markers). Pinned by `s5_unit_test.go`; the S5 differential (139 scenarios plus the S1 to S4 ones) runs the frozen script against authored fakes of gh, `reconcile-issues.sh`, `clean-check.sh` and `verify-state.sh`, and logs every child's argv. `status show` passes its own binary as `RSDD_BIN` to `verify-state.sh` (a shim that otherwise checks its source fingerprint, about 40-50 ms per call since kit #2599 against about 19 ms, plus a rebuild after a source change) unless the caller set one. Suites: the Go tests and differential in `rsdd/internal/status/show` (frozen excerpts under `testdata/legacy`) and `rsdd/internal/core/kit`. |
