### research-sdd-status (#2549)

| Tool | Description |
|---|---|
| `rsdd status show <target-dir> [--next\|--sync-state] [--focus <slug>] [--root]` | Go port (kit issue #2549, epic #2270) of `research-sdd-status.sh`, in slices (S1-S8); `research-sdd-status.sh` is now a compatibility shim over it (`rsdd_exec status show "$@"`) that hands over its own directory as `RSDD_TOOLBELT_DIR`, from which the command runs `verify-state.sh` and `reconcile-issues.sh`; the wiring is pinned by `tests/research-sdd-status-shim.test.sh`. Intended differences from the script (a legacy defect is fixed in Go, pinned by a test, and documented here; byte parity stays where a caller depends on the contract): (1) a state-file listing that fails in `--next` or `--sync-state` is `research-sdd-status: degraded: cannot list the state files under <dir>: <err>` on stderr and exit 1, no verdict, no write, where the script walked whatever list it got; (2) verify-state unavailable (`RSDD_TOOLBELT_DIR` unset, or `verify-state.sh` missing or not executable) is `research-sdd-status: degraded: verify-state unavailable (<reason>)` on stderr and exit 1, no verdict on stdout, where the script printed a STALE `reconcile first` or let the stopped-focus bypass hand out an unverified NEXT; (3) a verify-state killed by a signal is exit 128+signal (137 for SIGKILL), as the shell reports it; (4) a failed temp-file create or rename in `--sync-state` is a typed exit 1 where the script printed mv's error and still claimed `wrote`; (5) a slug or id holding a lone `)` is escaped before `grep -E` (kit finding F8), so it matches literally as GNU grep does. `--next` is whole in Go from slice S5 (the RETRO-DUE `covers_through` derivation, `issues_due_gate`, the terminal clean-check warning); the children it starts are exactly `gh issue list` (one read-only batch prefetch, bounded by `_IDG_RECONCILE_TIMEOUT_SECS`, default 15 s, `--limit` from `_IDG_BATCH_LIMIT`), this binary as `rsdd retro reconcile [--toolbelt <dir>] [--issues-cache <file>] <retro>` (one probe per unsettled retro, one re-verify per retro the batch calls untracked; no bash and no `reconcile-issues.sh` shim in between) and, in place of the former `bash <toolbelt>/clean-check.sh --target <dir>`, the in-process `core/cleancheck` (only without `RSDD_STATUS_NO_CLEAN_CHECK=1`; see (22)-(24)); no gh write ever runs. Further intended differences, all from slice S5: (6) the bound of every child is `core/proc`'s, not `timeout(1)`/`gtimeout`, so the script's "no timeout binary" states and the `_IDG_TIMEOUT_BIN` test hook do not exist, an unusable `_IDG_RECONCILE_TIMEOUT_SECS` (the script made `timeout` fail every call with exit 125) is the default 15 s, and clean-check's two streams were read stdout then stderr instead of interleaved by `2>&1` (superseded by (23)); (7) a probe's stderr and the batch are captured in memory, so the script's `mktemp failed for retro enumeration`, `... for retro enumeration stderr`, `... cannot capture reconcile stderr`, awk-count and sort-failure warnings cannot occur, while `mktemp failed for issue-cache` (the batch cache file) stays and no longer makes the script skip every probe; (8) the retro listing is in byte order whatever the locale (the gate's `sort` followed the caller's locale, the derivation's `LC_ALL=C`), so the first retro that is untracked is the same on every machine; (9) the block-id digits of the newest-block scan are the second-to-last regex group, not `BASH_REMATCH[2]`, so a focus prefix that holds its own `( )` group no longer feeds a prefix fragment into the arithmetic; (10) the script's `lib/retro-status.sh not found` warnings are gone with the sourced helper (`core/retrogrammar` reads the markers). Pinned by `s5_unit_test.go`; default report (S6, pinned by `s6_unit_test.go`): (11) a failing state-file listing refuses the run before any output, as `--next` does; (12) the blocked-rows probe's rc 3 has no counterpart; (13) awk diagnostics for unreadable ledgers are not reproduced; (14) a `verify-state` that cannot run (exit 126/127: `RSDD_TOOLBELT_DIR` unset, script missing or not executable) adds the typed line `  consistency: DEGRADED — verify state could not run (<why>)` under the consistency header, where the script printed an empty block; the default report still exits 0, as it has no degraded exit (kit issue #2736); (15) sort tie-breaks on the whole line are bytewise (C locale), the script's follow the caller's locale; (16) iteration-history counts beyond 2^53 are not modelled; campaign queue and document cycle (S7, pinned by `s7_unit_test.go`): (17) `last_iteration_ts` is read as ISO-8601 only, so `date -d` phrases such as `yesterday` give `unknown`; (18) `_RSDD_NOW_EPOCH` is a test hook that falls back to the clock when it is not an integer; (19) an Outline row with an empty item cell keeps its status and a tab inside an item is kept (the script's tab-IFS `read` collapsed empty fields and shifted the row); (20) the script's refusals when a sourced lib is missing or defines nothing have no counterpart, because the logic is compiled in: `lib/gh-visibility.sh` missing with a remote printed `degraded: remote-visibility: lib/gh-visibility.sh unavailable` (exit 0); now the probe runs through `core/gh`, and a gh that cannot answer still gives a typed `degraded: remote-visibility: gh not found|gh failed (rc=N)|gh timed out ...` line (pinned by `s6_scen_vis_test.go` v-gh-* scenarios); `lib/hook-wiring.sh` missing (`cannot find helper`, exit 1, no report) or defining no `hook_stop_wiring_state` (`failed to define`, exit 1) — now the report runs (exit 0) with the Stop hook line from `core/hookwiring`; `lib/blocked-rows.sh` missing or empty (exit 1, a message naming blocked-rows) — now the report runs (exit 0) and reads blocked rows in process; (21) the per-file blocked-rows probe names only the head state: an unreadable NON-head state file was reported by the script as `DEGRADED (blocked-rows derivation unreadable for <file> ...` (report) or `... unreadable for <rel-path> ...` (`--next`); the port reports it from the walk as `DEGRADED | blocked-rows read failed while resolving <gap> in <rel-path> — no gap is handed out ...`, still naming the file by its path relative to the target; exit codes unchanged (`--next` 3, report 0), and the report still prints its one reason-codes footer, after that next-step line (pinned by `s8a_blocked_test.go`); the terminal clean-check (kit issue #2549, pinned by `cleanwarn_test.go`): (22) it runs `core/cleancheck` in process, so there is no `clean-check.sh` lookup and the `unverifiable (clean-check.sh not found beside research-sdd-status.sh) — terminal no-garbage check NOT run` WARN no longer exists (a missing toolbelt cannot disable the check; the S5 scenario `cc-script-not-beside-the-status-script` is retired); (23) its two streams are read in print order (`Result.Merged`), not stdout then stderr as the subprocess pipe gave them; (24) the context deadline (`RSDD_STATUS_CLEAN_CHECK_TIMEOUT`, default 20 s) stops the git children itself, so there is no 5 s kill grace and no exit 137: a timeout is only `unverifiable (timed out after Ns)` and never a clean claim (the S5 scenario `cc-exit-137-is-a-timeout` is retired); the S5 differential (139 scenarios plus the S1 to S4 ones) runs the frozen script against authored fakes of gh, `reconcile-issues.sh` and `verify-state.sh` (the oracle's own fake `clean-check.sh` answers the script; the Go side replays the same `cc.rc`/`cc.out` through the in-process seam), and logs every child's argv. `status show` passes its own binary as `RSDD_BIN` to `verify-state.sh` (a shim that otherwise checks its source fingerprint, about 40-50 ms per call since kit #2599 against about 19 ms, plus a rebuild after a source change) unless the caller set one. Suites: the Go tests and differential in `rsdd/internal/status/show` (frozen excerpts under `testdata/legacy`) and `rsdd/internal/core/kit`. |
