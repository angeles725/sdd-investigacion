### research-sdd-status (#2549)

| Tool | Description |
|---|---|
| `rsdd status show <target-dir> [--next\|--sync-state] [--focus <slug>] [--root]` | Go port (kit issue #2549, epic #2270) of `research-sdd-status.sh`, in slices; the script stays authoritative until the last slice makes it an `rsdd_exec` shim. Intended differences from the script (a legacy defect is fixed in Go, pinned by a test, and documented here; byte parity stays where a caller depends on the contract): (1) a state-file listing that fails in `--next` or `--sync-state` is `research-sdd-status: degraded: cannot list the state files under <dir>: <err>` on stderr and exit 1, no verdict, no write, where the script walked whatever list it got; (2) verify-state unavailable (`RSDD_TOOLBELT_DIR` unset, or `verify-state.sh` missing or not executable) is `research-sdd-status: degraded: verify-state unavailable (<reason>)` on stderr and exit 1, no verdict on stdout, where the script printed a STALE `reconcile first` or let the stopped-focus bypass hand out an unverified NEXT; (3) a verify-state killed by a signal is exit 128+signal (137 for SIGKILL), as the shell reports it; (4) a failed temp-file create or rename in `--sync-state` is a typed exit 1 where the script printed mv's error and still claimed `wrote`; (5) a slug or id holding a lone `)` is escaped before `grep -E` (kit finding F8), so it matches literally as GNU grep does. `status show` passes its own binary as `RSDD_BIN` to `verify-state.sh` (a shim that otherwise re-hashes the Go sources, about 1.1 s per call against 19 ms) unless the caller set one. Suites: the Go tests and differential in `rsdd/internal/status/show` (frozen excerpts under `testdata/legacy`) and `rsdd/internal/core/kit`. |
