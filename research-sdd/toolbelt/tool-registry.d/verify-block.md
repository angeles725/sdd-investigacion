### verify-block (#2456)Shared-helper note (kit issue #2600): the Go block-file patterns and the scripts-manifest row reader have one definition each, in `internal/core/kit` (`blockfiles.go`, `scriptsmanifest.go`), shared with the other Go consumers; `lib/block-files.sh` and `lib/scripts-manifest.sh` still serve the bash scripts not yet ported (`clean-check.sh`), so a change to one of those libraries must be mirrored in `core/kit`. One pinned variant: the block-file slug class is `[[:alnum:]_-]` (C locale) in `lib/block-files.sh` and in `kit.BlockFileRE`, but verify block matches `[\p{L}\p{N}_-]` (`kit.BlockFileNameUnicode`, `kit.BlockPathUnicode`), because the script's `awk` ran under the caller's UTF-8 locale; both are derived from one tail (`blockTailFor`) and pinned by `blockpattern_test.go`, so a block file with a non-ASCII slug is canonical to verify block and not to the C-locale consumers. |

| `rsdd verify block [--strict-ephemeral \| --ephemeral=warn\|fail] [--extern-check] [--backptr=high\|all\|off] <block.md> [target-dir]` / `rsdd verify block --possibility-sweep <corpus-dir>` | Go port (kit issue #2456, epic #2270) of `verify-block.sh`; the registry row `verify-block.sh <block.md>` above still describes what it checks and prints, byte for byte, and its legacy exit contract holds: 0 clean, 1 a failing check (`RANGE!`, `EPHEMERAL!` under the FAIL default, a manifest mismatch), 2 bad arguments. `verify-block.sh` is a compatibility shim that hands over to `lib/rsdd-exec.sh`; it is removed in phase 8. The frozen script and the libraries it sourced are the parity oracle of the Go differential tests (`internal/verify/block/testdata/block-legacy`), which replay every invocation the retired bash suites made. Acceptance fleet sweep: every block of every `TARGETS.md` corpus (6,875 blocks, the four flag sets on every tenth) gave identical stdout and exit code under the host locale (`C.UTF-8`) in all 8,936 runs, and identical stderr in all but 47 (below). Intended differences: text is measured in characters, as `awk` does under a UTF-8 locale, whatever the caller's locale — under `LC_ALL=C` the script counted bytes, so the back-pointer proximity window and the 110-character sentence excerpt differed on non-ASCII blocks (166 of 8,936 sweep runs, all in the back-pointer section, no exit code changed); `awk`, `find`, `grep`, `jq` and `sha256sum`/`shasum` are no longer run, so the degraded branches for a missing or failing tool do not exist; an unreadable block reports the same DEGRADED lines and exit 1 as the script, but stderr carries one `verify-block.sh: cannot read <block>: <error>` line instead of the script's twenty-odd `awk`/`grep`/`cat` `Permission denied` lines (pinned by `TestDifferentialBlockUnreadable`); the lines printed for an unreadable cited file (not the block) are not pinned against the script; a bash test over a non-integer (`[: integer expression expected`) prints no stderr line; files gathered for the OCR and possibility sections are listed in byte order, where the script used `find`'s readdir order, which depends on the filesystem (kit issue #2477); a block holding invalid UTF-8 no longer gets `gawk`'s `warning: Invalid multibyte data detected` lines on stderr (the 47 runs above, all the `invalid_utf8` replay fixture copied across kit worktrees; stdout and exit code unchanged). Shared-helper note: `lib/block-files.sh` and `lib/scripts-manifest.sh` still serve `verify-registry.sh`, `verify-corrections.sh` and `clean-check.sh`; the Go block-file and manifest logic here is a separate copy, so a change to one of those libraries must be mirrored here until those consumers are ported too. |
