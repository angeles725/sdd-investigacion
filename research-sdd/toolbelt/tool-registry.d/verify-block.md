### verify-block (#2456)

| Tool | Description |
|---|---|
| `rsdd verify block [--strict-ephemeral \| --ephemeral=warn\|fail] [--extern-check] [--backptr=high\|all\|off] <block.md> [target-dir]` / `rsdd verify block --possibility-sweep <corpus-dir>` | Go port (kit issue #2456, epic #2270) of `verify-block.sh`; the registry row `verify-block.sh <block.md>` above still describes what it checks and prints, byte for byte, and its legacy exit contract holds: 0 clean, 1 a failing check (`RANGE!`, `EPHEMERAL!` under the FAIL default, a manifest mismatch), 2 bad arguments. `verify-block.sh` is a compatibility shim that hands over to `lib/rsdd-exec.sh`; it is removed in phase 8. The frozen script and the libraries it sourced are the parity oracle of the Go differential tests (`internal/verify/testdata/block-legacy`), which replay every invocation the retired bash suites made. Acceptance fleet sweep: every block of every `TARGETS.md` corpus (6,875 blocks, the four flag sets on every tenth) gave identical stdout and exit code under the host locale (`C.UTF-8`) in all 8,936 runs, and identical stderr in all but 47 (below). Intended differences: text is measured in characters, as `awk` does under a UTF-8 locale, whatever the caller's locale — under `LC_ALL=C` the script counted bytes, so the back-pointer proximity window and the 110-character sentence excerpt differed on non-ASCII blocks (166 of 8,936 sweep runs, all in the back-pointer section, no exit code changed); `awk`, `find`, `grep`, `jq` and `sha256sum`/`shasum` are no longer run, so the degraded branches for a missing or failing tool do not exist; the lines printed for an unreadable (permission-denied) cited file are not pinned against the script; a bash test over a non-integer (`[: integer expression expected`) prints no stderr line; files gathered for the OCR and possibility sections are listed in byte order, where the script used `find`'s readdir order, which depends on the filesystem (kit issue #2477); a block holding invalid UTF-8 no longer gets `gawk`'s `warning: Invalid multibyte data detected` lines on stderr (the 47 runs above, all the `invalid_utf8` replay fixture copied across kit worktrees; stdout and exit code unchanged). |
