### merge-gate (phase 8 slice 8.0)

| Tool | Description |
|---|---|
| `rsdd gate merge` (shim: `merge-gate.sh`) | Declared divergence from the frozen bash original (`rsdd/internal/gate/testdata/legacy/merge-gate.sh`), CI gate only: a check in the REQUIRED list (`--required-checks`, else `MERGE_GATE_REQUIRED_CHECKS`, else `shellcheck,toolbelt-tests`) must conclude `success`. The original counted `skipped` and `neutral` as green for every check, so a required check GitHub reported as skipped merged as `ok`; now the latest run of a required name that concluded `skipped` or `neutral` refuses with `refuse: ci_skipped (name[,name])` (names unique and sorted, exit 1). `skipped` and `neutral` stay acceptable for checks outside the required list (`toolbelt-extras` is skipped on every PR). The path-filter exemption (kit issue #1867) only removes a required name that has NO check run at all (its workflow did not run for this diff); a required name that has a run concluded `skipped` or `neutral` is never exempted and is refused. Precedence of the CI refusals: `ci_failed`, `ci_pending`, `ci_skipped`, `ci_missing`. The main table row above still describes the rest of the contract; its "success/skipped/neutral" wording applies to non-required checks only. Pinned by `TestCIVerdict` and `TestCISkippedRequiredDiverges` (the original answers `ok`, the port `ci_skipped`); every other CI case stays byte-identical in the differential test. |
