### serial-frame (#2437)

| Tool | Description |
|---|---|
| `rsdd serial frame-analyze stats\|diff\|checksum ...` / `rsdd serial frame-capture sweep\|capture ...` | Go port (kit issue #2437, epic #2270, unit U6.23-U6.24) of `serial-frame_analyze.py` and `serial-frame_capture.py` (`rsdd/internal/serial/frame*.go`, `serialport_*.go`). The rows for `serial-frame-analyze.sh` / `serial-frame-capture.sh` above and their contract ([`serial-frame.v1`](../serial-frame.v1.md)) still describe the behavior, unchanged (exit codes, evidence schema, caps, refusals). Both `.sh` entry points are compatibility shims over `lib/rsdd-exec.sh` (`$RSDD_BIN`, then `<kit>/bin/rsdd`); they are removed in phase 8. The Python files are gone; the frozen scripts live under `rsdd/internal/serial/testdata/legacy/` as the differential oracle of the Go tests (the capture oracle runs against a stub `serial` module and a fake clock). The live port is driven through termios on Linux (no pyserial): raw 8N1, no flow control, pyserial's read-timeout semantics and open/configure error texts; other systems report the port unavailable (exit 2). Intended differences: a non-regular analyze input (FIFO, device, socket) is refused with exit 2 instead of blocking or reading without end; plan-only exit 3 also prints one `DEGRADED:` line on stderr (the rsdd exit-3 contract); `--seconds` / `--gap-ms` refuse `inf` and `nan` (they would put non-JSON tokens in the document); a negative `--baud` with `--allow-live-probe` is a typed exit 2 instead of a traceback; usage errors use the Go parser's argparse-style wording (exit 2 as before); a path argument that is not valid UTF-8 cannot be encoded into the document and is refused. |
