### ci-shard (kit issue #2753, slice 8.2a of the Go CI join)

| Tool | Description |
|---|---|
| `rsdd maint ci-shard plan --shard I/N [--durations FILE]` | Pure planner for the Go CI shards (it never runs `go test`): reads the package list on stdin (one import path per line, blanks skipped, a missing final newline is fine) and prints this shard's packages, sorted, on stdout. The rule is the one of `run-all.sh --shard I/N`: packages longest first (ties: path, byte order) go to the least-loaded shard (ties: the lowest shard number), so the N plans are a disjoint and complete cover of the list for every N from 1 to 32 (`--shard` is `^[0-9]{1,3}/[0-9]{1,3}$` with 1 <= I <= N <= 32, else exit 2). `--durations FILE` holds `<package> <seconds>` lines (`#` comments and blanks skipped; seconds a positive integer of at most six digits): a package it does not list weighs 6 s and is named on stderr, an entry naming no planned package is ignored and named (`stale duration entries N`), and an invalid line (no seconds, extra text, bad seconds, a package twice) is `INVALID` and exit 1 before anything is planned. No usable file (not given, absent, unreadable, no entry, no entry for a planned package) is a typed `DEGRADED` note on stderr and the assignment by position in the sorted list (exit 0, as the bash runner): with no weight every package weighs the same, which makes the greedy rule exactly position mod N. An empty result is never a pass: zero bytes (`empty-input`), bytes with no package (`no-match`), no stdin (`absent-input`), a package twice or a path holding whitespace (`INVALID`), and a shard whose own share is empty because N exceeds the package count (`EMPTY SHARD`) are all exit 1 with nothing on stdout. |
| `rsdd maint ci-shard manifest --shard I/N --exit RC --planned FILE` | Reads the `go test -json` stream of one shard on stdin and the shard's plan (the output of `plan`) from `--planned`, and writes on stdout the manifest `shard-join.sh` reads unchanged: `# shard I/N suites=K exit=RC`, then `<import path> PASS\|FAIL\|SKIP` per planned package in the planned order. A row is the LAST package-level `pass`, `fail` or `skip` of the stream; a planned package with no such event is `FAIL` and a `no-final-event` finding. `--exit RC` (0 to 255) is the status of `make` itself, taken after the stream was written to a file, never the status of a pipeline. The manifest fails the join on its own: with ANY finding and RC 0 the header is written `exit=1` (one stderr line `header exit raised to 1 because of findings: <kinds>`), a non-zero RC is written as given, and report-only lines never change the header. Findings (stderr, `ci-shard: FINDING — <kind>: ...`, exit 1, the manifest is still written): `empty-input`, `no-events`, `malformed-lines`, `unplanned-package`, `no-final-event`, `exit-0-with-fail`, and `exit-nonzero-no-fail` (a non-zero RC and no `FAIL` row, whatever mix of `PASS` and `SKIP` rows; the message names the exit code and the PASS/SKIP counts). Every run also prints the report lines `Go tests skipped: N — [pkg: n]` (test-level skips counted from the stream: a package whose tests all skip ends in a package-level `pass`, which `shard-join.sh --strict-skip` cannot see; report-only) and `unknown actions: N — [names]` (an `Action` the writer does not know, counted and named, report-only). Exit 0 clean, 1 finding or operational failure, 2 usage. |

Package: `rsdd/internal/maint/cishard` (plan: `plan.go`, `planlist.go`, `plandurations.go`, `planassign.go`, `planreport.go`; manifest: `manifest.go`, `manifeststream.go`, `manifestrows.go`, `manifestreport.go`; shared: `cishard.go`, `shardspec.go`, `files.go`). Stdout carries the data and stderr the typed notes. Pinned by recorded `go test -json` streams under `internal/maint/cishard/testdata/gotestjson` (the README beside them records the Go version and the command), which show that a build failure and a crashed test binary (`os.Exit(3)` in `TestMain`) both end in a package-level `fail`, and by a test that feeds manifests written by the command to the real `toolbelt/tests/shard-join.sh`.

Decisions the issue text does not state (each pinned by a test): a package listed twice in a list is `INVALID` (the assignment would place it in two shards); a path holding whitespace is `INVALID`; the plan prints in path order; `--durations` not given reads as `DEGRADED`; unreadable stream lines are a finding, not a silent drop.
