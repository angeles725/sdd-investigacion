# Quality gate reference

Full reference for `## 5. Quality Gates` in the root `CLAUDE.md`, moved here verbatim so the root file stays small.
The root file keeps the short normative rules; this file holds the per-gate detail (every `run-all.sh` flag, its
sentinels, issue numbers and incident evidence). References such as "§5" or "the Tier row" in other files point at
the root `CLAUDE.md` section or at the matching row below.

## Quality gate reference

| Gate | Command | Standard |
|---|---|---|
| Shellcheck | `shopt -s globstar && shellcheck -S warning research-sdd/toolbelt/**/*.sh research-sdd/install/**/*.sh` | Zero warnings. **`globstar` is required** — without it the glob matches depth 1 only, silently skipping all of `lib/` and `tests/`. `shopt` is a bash builtin: under zsh it errors out, but zsh globs `**` recursively on its own, so the coverage is still correct — check the file count, not the absence of an error. `.shellcheckrc` suppresses SC2015 and SC2016 — intentional silences for this codebase's idioms, not blanket ignores. `research-sdd/install/**/*.sh` is a second, separate tree (`adapters.sh`, `install.sh`, `research-sdd-install.sh`, `tests/research-sdd-install.test.sh`) outside `research-sdd/toolbelt/` — the toolbelt glob alone does not cover it (kit issue #1126) |
| Test suite | `bash research-sdd/toolbelt/tests/run-all.sh` | One gate command traverses BOTH corpora: `research-sdd/toolbelt/tests/*.test.sh` and `research-sdd/install/tests/*.test.sh` (kit issue #1126 — CI already ran the install corpus, this local gate did not, so a PR could be green locally and still fail CI). The final AGGREGATE RESULT block declares each corpus and its suite count as its own line (§7) — after all suites have run, not before; the `Corpus:` lines count the full discovered set, while the `Tier:` line states what actually ran (the default is the core tier, see the Tier row). All suites of the selected (default core) tier pass; skipped ≠ passed; zero-coverage run exits 1; an ABSENT install/tests corpus exits 1 even if every discovered suite passes (kit issue #1144 — a moved/renamed corpus must not read as a silent pass; an EMPTY install/tests dir is reported distinctly and does not fail the gate by itself). The aggregate also prints, right after the caller-cwd line, `Kit-tree hermeticity violations (new/modified/removed files under research-sdd/): N` (or `Kit-tree hermeticity: DEGRADED — <reason>; could not verify`): `research-sdd/` is snapshotted by path + sha1 around every suite, so a suite that writes into the repo tree (kit issue #1156) is named and the run exits 1; `__pycache__` and directories are not tracked and an identical-bytes rewrite is not a change (anchored by `# SENTINEL-KIT-TREE-CHECK`). Every run also creates ONE temp root under the caller's `TMPDIR` (else `/tmp`), exports `TMPDIR` to a per-suite subdir (serial and `-j`), removes the root on EXIT unless `--keep-tmp` is given (then it keeps the root and prints `TMPDIR kept: <path>`, or `TMPDIR kept: none (...)` when no root could be created), and prints `TMPDIR leftovers: N — [suite: count]` right after the kit-tree block (N = total entries left in the suites' subdirs, dotfiles included, one entry per name so a name containing a newline counts once; or `TMPDIR leftovers: DEGRADED — <reason>; could not verify`). A `TMPDIR scan: DEGRADED` line follows only when a scan or creation failed, and it names only the clause(s) that apply. It is report-only by default; the opt-in `--require-clean-tmp` flag exits 1 on any leftover or a DEGRADED state (anchored by `# SENTINEL-TMPDIR-ROOT`, `# SENTINEL-TMPDIR-REPORT`, `# SENTINEL-REQUIRE-CLEAN-TMP-EXIT`). The same line also folds in NEW entries a suite created in the default host root `/tmp/rsdd` (the VM/Docker run-dir fallback when `$RSDD_VM_ROOT` is unset, which neither the per-suite TMPDIR nor the kit-tree check covers — kit issue #2164), shown as `suite: n (in /tmp/rsdd)`, and entries a suite REMOVED as `suite: removed n (in /tmp/rsdd)` (a names-only diff: an entry rewritten under the same name is not seen); entries that pre-existed are never blamed for existing, an absent root is empty, an unscannable one is a typed `TMPDIR scan: DEGRADED`, and under `-j` the check runs once for the batch under the label `-j batch (default rsdd root: per-suite attribution not attempted)` (anchored by `# SENTINEL-RSDD-DEFAULT-ROOT`; `RUN_ALL_DEFAULT_RSDD_ROOT` is a test hook for run-all.test.sh only). Suites that drive a run-dir allocator must set `RSDD_VM_ROOT` to a sandbox under their TMPDIR (the VM tooling whose allocator this guarded, and its `run-all-default-root.test.sh` guard, were retired by kit issue #2443). The runner also builds the `rsdd` binary ONCE per invocation (kit issue #2422), after the arguments are validated and before any suite runs (never for `--list-suites` or a refused flag), into its own temp root (`research-sdd/rsdd`, the Makefile `build` recipe with the stamped source hash; anchored by `# SENTINEL-RSDD-BIN-BUILD`) and exports `RSDD_BIN` to every suite (`# SENTINEL-RSDD-BIN-EXPORT`), so `lib/rsdd-exec.sh` never rebuilds into `research-sdd/bin` and trips the kit-tree check; a caller-set `RSDD_BIN` is used as-is (`# SENTINEL-RSDD-BIN-CALLER`). The aggregate prints exactly one `rsdd:` line right after the `Tier:` line: `rsdd: built — ...`, `rsdd: RSDD_BIN set by the caller — ...`, `rsdd: SKIPPED — no Go module at ...` (a fixture or partial tree; never fails) or `rsdd: DEGRADED — <reason>` (go absent, no temp root, or the build failed; `RSDD_BIN` stays unset and the shims degrade on their own). A DEGRADED build exits 1 under `RSDD_REQUIRE_GO=1`, which CI sets (`# SENTINEL-RSDD-BIN-REQUIRE`), and is otherwise report-only. One build per invocation also under `-j N` and `--shard I/N` (the workers inherit the environment). |
| Mutation | `bash research-sdd/toolbelt/tests/run-all.sh --prove-teeth` | All mutation controls go red |
| Parallel (opt-in) | `bash research-sdd/toolbelt/tests/run-all.sh -j N` (N ≤ 6) | Same aggregate as serial plus one `Parallel:` line; hermeticity guards snapshot once around the batch, and a leak found there triggers a serial re-run bounded to the candidate suites whose recorded run window contained the leaked path's mtime (the suites whose recorded window matched — typically at most `N`, never the whole corpus; per-suite timeout `RUN_ALL_ATTRIBUTION_TIMEOUT`, default 600 s; a value that is not a positive integer yields a typed `Attribution:` line and the default; a `date` without `%N` falls back to whole-second run windows with a 1 s match tolerance), blaming the one whose re-run changes the path's mtime or content hash; anything unattributable (a removal, no matching window, no usable `stat`) keeps the typed batch label plus a typed `Attribution:` line saying why, and still fails the run. A clean `-j` run and the serial path are untouched. No usable GNU parallel → typed `DEGRADED` + serial, and the line names the concrete cause (not on PATH / not GNU parallel / `--version` fails). Serial stays the reference for the quiet-tree gate (§3) |
| Lane (opt-in) | `bash research-sdd/toolbelt/tests/run-all.sh --lane <fast\|slow\|all>` | Exports `RSDD_TEST_LANE` to every suite (kit issue #1821) so the lane-aware suites (`tests/lib/test-lane.sh`: fast = fixture-cached, slow = real tool, all = both) run that lane; also accepts `--lane=<name>` and combines with `--prove-teeth` and `-j N`. The value is validated by the lib's own `rsdd_lane`, and a missing or unknown value (or an absent lib) exits 2 before any suite runs. The aggregate prints one `Lane: <name>` line after the corpus lines. Without the flag the caller's ambient `RSDD_TEST_LANE` is left untouched (anchored by `# SENTINEL-LANE-EXPORT`) |
| Cache (opt-in) | `bash research-sdd/toolbelt/tests/run-all.sh --cache` | Kit issue #2201 part 2: a suite whose content key is unchanged reuses its previous full PASS (output replayed, labelled `(cached)`, counted as passed), so flake reruns, restacks and small PRs skip unchanged suites. The key is a sha256 over the suite file, its forward dependency set (`suite-impact.sh --deps-all`), `tests/lib/**`, `run-all.sh`, the impact/tier manifests, the install and templates trees, the run mode (`--prove-teeth`, lane; not the tier), `id -u`, the path and first `--version` line of bash/python3/node/git/jq/shellcheck/bwrap/unshare/parallel/qemu-system-*/tshark/binwalk/docker, `tests/shard-join.sh`, and the `RSDD_*` environment (`%q`-encoded) (anchored by `# SENTINEL-CACHE-GLOBAL`), except `RSDD_BIN`: a path (a temp path when run-all built it) is never key material, so the key instead carries the sha256 of the binary when the caller set `RSDD_BIN` and the hash of every file under `research-sdd/rsdd/` (the module sources run-all builds from) otherwise (anchored by `# SENTINEL-RSDD-BIN-CACHE` and `# SENTINEL-RSDD-BIN-CACHE-SRC`). Always-run suites (`impact-always.txt`, whole-tree readers), blind-spot suites and suites with no resolvable dependencies are NEVER cached (reason printed); only a full PASS is stored (never a FAIL, any output line starting `SKIP`, or a suite with a hermeticity finding); cached suites are not hermeticity-checked and the aggregate says how many. Entries live under `${XDG_CACHE_HOME:-$HOME/.cache}/research-sdd/run-all/` (a cache dir inside the repo is refused). The aggregate prints `Cache: hit H, miss M, uncacheable U — [suite: reason]`, `Cache hits:` and `Cache stored:`; any state it cannot establish is a typed `Cache: DEGRADED` and the run proceeds without the cache. **Refused (exit 2) with `--require-teeth` and `--shard`: the authoritative per-batch gate and CI never use it** — run the quiet-tree gate without `--cache`. Known limits: the key cannot see state outside `research-sdd/` and the named groups (the host's commit history, `$HOME`, the network) or tools beyond those listed. `--no-cache` is the explicit default (anchored by `# SENTINEL-CACHE-REFUSE`) |
| Tier (default core) | `bash research-sdd/toolbelt/tests/run-all.sh [--tier core\|extras\|all]` | Kit issue #2203: the DEFAULT gate runs only the core tier. `research-sdd/toolbelt/tests/suite-tiers.txt` lists the EXTRAS suites (category E VM/dynamic sandbox, unused adapters, strict-zero usage), one `<repo-relative suite> extras <reason>` per line; nothing is deleted. `--tier extras` runs only those, `--tier all` both (also `--tier=X`; an invalid value exits 2 before any suite runs). The manifest is parsed strictly like `teeth-helper-waivers.txt`: a line with no reason, a tier word other than `extras|dedicated`, a duplicate, or a path naming no discovered suite prints `Tier: INVALID` and exits 1 BEFORE any suite runs, so a renamed suite cannot silently drop out of the gate; an absent or unreadable manifest prints `Tier: DEGRADED`, runs ALL suites and exits 1 (§7); a tier selecting 0 suites prints `Tier: EMPTY` and exits 1 (anchored by `# SENTINEL-SUITE-TIER`). The aggregate prints `Tier: <t> — K of T suites (excluded: N)` (T = every discovered suite). The filter applies before `--list-suites` and `--shard`, so both operate on the selected tier, while discovery, the empty-list check and the install-corpus ABSENT gate judge the full set. `--require-teeth` implies `--tier all` (see the Teeth coverage row). CI: the PR/push shards and the `toolbelt-tests` join run `--tier core` explicitly; the separate `toolbelt-extras` job in `.github/workflows/toolbelt-tests.yml` runs `--tier extras --prove-teeth -j 4` only on the nightly `schedule` and on `workflow_dispatch`. A change touching a SUT or lib exercised by an extras suite also runs `run-all.sh --tier extras` (or `--tier all`) before gating; the nightly job runs after merge and does not replace that. A third tier word, `dedicated` (kit issue #2488), marks a suite that runs in its OWN CI job: it is in neither core nor extras (so the toolbelt shards and `shard-join.sh --tier core` expect exactly the other suites), it runs only under `--tier all` (so `--require-teeth` still judges it), and its reason names the job — today `rsdd-go.test.sh` in the `rsdd-go-bridge` job of `.github/workflows/rsdd-go.yml` (on pull_request and push a matrix of three jobs named `rsdd-go-bridge (I/3)`, each running its share of the changed non-test `.go` files (file position mod 3, so even a one-package change spreads over the three; a change with no `_test.go` edit mutates only its changed files, and unchanged sibling files are covered by the nightly run) through `RSDD_TEETH_SHARD=I/3` and `RSDD_BRIDGE_PART=teeth`, kit issues #2568 and #2573, while the whole-module `make test` and the panic-boundary control run in the parallel `rsdd-go-test` job (`RSDD_BRIDGE_PART=test`, kit issue #2617); path-filtered to the whole kit, `research-sdd/**`, and the workflow, because Go tests read live kit files as differential oracles (a PR that changes no Go package gets the typed `teeth: n/a`), plus a nightly whole-module run). A new suite is core unless added to the manifest; to run an extras suite locally run `run-all.sh --tier extras` or the suite file directly. |
| Impacted (opt-in, per-PR) | `bash research-sdd/toolbelt/tests/run-all.sh --impacted <base-ref>` | Kit issue #2201: the fast local gate for a PR in flight. Runs only the suites `suite-impact.sh` selects for merge-base(`<base-ref>`, HEAD) → working tree (uncommitted edits count), intersected with `--tier`; **it never replaces the per-batch full gate above, which stays the authoritative one**. An escalation (the class list is the `suite-impact.sh` header: harness files, `install/**`, `templates/**`, `.github/**`, added/deleted/renamed production files, widely used libs, anything unplaceable) runs the whole tier selection unchanged and prints `Impacted escalated: FULL — <reason>`. The aggregate declares `Impacted: K of T suites (base <ref>, merge-base <sha>)`, one escalation line (`Impacted escalated: no` or `FULL — <reason>`) and a skipped count; an impacted suite outside the tier is named, not run. Anything `suite-impact.sh` cannot answer is a typed `Impacted: DEGRADED` and exit 2 before any suite runs, an empty selection inside the tier is `Impacted: EMPTY` (exit 1) — never a partial set. Refused with `--shard` and `--require-teeth` (exit 2: both judge the whole corpus); `--list-suites` lists the selection and `--keep-tmp` keeps it as `impacted.txt`. `--prove-teeth` is allowed and then covers only the selected suites |
| Flake hunt (nightly CI, opt-in local) | `bash research-sdd/toolbelt/maint/kit-flake-hunt.sh --runs 3 --prove-teeth --load 2 --tier core --file-issues` | Kit issue #2209: runs each suite K times under bounded CPU load and reports every suite that failed at least once (`flaky`) or in every run (`broken`); `--file-issues=apply` files or comments on ONE `flake: <suite> ` issue per such suite. CI: `.github/workflows/flake-hunt.yml` runs it nightly (`schedule`) and on `workflow_dispatch` (inputs `runs`, `load`, `tier`), sharded 4 ways because one serial pass over the core list does not fit the 6 h hosted-job cap (`runs` is capped at 4 by the job timeout; the whole out dir with logs and issue bodies is uploaded per shard and each issue body carries the run URL via `--evidence-url`; the suites run without `GH_TOKEN`/`GITHUB_TOKEN`; the job runs only in `angeles725/sdd-investigacion`); it is NOT a PR check and not part of the required `toolbelt-tests` join. Read its header for flags and exit codes. |
| Shard (opt-in, CI) | `bash research-sdd/toolbelt/tests/run-all.sh --shard I/N [--shard-manifest PATH]` + `bash research-sdd/toolbelt/tests/shard-join.sh --shards N MANIFEST...` | Kit issue #2114: CI runs the gate as a matrix of N shards because the single job reached its cap. `--shard I/N` (N ≤ 32; invalid → exit 2 before any suite runs; also `--shard=I/N`) sorts the selected tier's list of BOTH corpora (the default core tier; the full list under `--tier all`, see the Tier row) by repo-relative path (`LC_ALL=C`) and, since kit issue #2488, assigns them by measured duration: `research-sdd/toolbelt/tests/suite-durations.txt` (`<repo-relative suite> <seconds>`, seeded from one green main run and refreshed by hand when the shard totals drift) weights each suite, and suites go longest-first (ties: path) to the least-loaded shard (ties: lowest shard number) — deterministic, a disjoint and complete cover for every N (anchored by `# SENTINEL-SHARD-ASSIGN`, validation by `# SENTINEL-SHARD-VALIDATE`, manifest parsing by `# SENTINEL-SHARD-DURATIONS`). A selected suite the manifest omits weighs 6 s and is named on stderr; an invalid line (not `<path> <positive integer>`, or a duplicate) is a typed `Shard: INVALID` and exits 1 before any suite runs; an entry naming no discovered suite (a renamed or removed suite, routine in port PRs) is ignored and named on one aggregate line `Shard: stale duration entries N — [paths]`, exit unaffected (a stale weight costs balance, never correctness); an absent, unreadable or empty manifest is a typed `Shard: DEGRADED` note and the older assignment (0-based position mod N is I−1; still a disjoint cover, exit unchanged). The aggregate prints `Shard: balance — duration-weighted, predicted S s for this shard (all N shards: min .. s, max .. s)`, or `Shard: DEGRADED — ...` in the fallback. The weights steer which shard runs a suite, never whether it runs. Discovery, the empty-list check and the install-corpus ABSENT-INPUT gate (#1126/#1144) stay over the FULL discovered set. The aggregate prints `Shard: I/N — K of T suites`; K = 0 (N > T) prints `EMPTY SHARD`, exits 1 and is never a pass (`# SENTINEL-SHARD-EMPTY`). `--shard-manifest` writes `# shard I/N suites=K exit=RC` then `<repo-relative suite> <PASS\|FAIL\|SKIP>` per suite (`# SENTINEL-SHARD-MANIFEST-WRITE`; the header carries the shard's own exit code, so a shard failed by a hermeticity/teeth gate with every suite PASS still fails the join). `run-all.sh --list-suites [--tier T]` prints the selected tier's list (the join's single discovery source). `shard-join.sh [--tier T]` (default core, passed to `--list-suites`) exits 0 only when every suite ran exactly once, passed, in a complete set of green shards; it names missing, duplicated, failed and unexpected suites, missing/duplicate shards, and absent/corrupt manifests (typed `JOIN:` findings, exit 1; usage → 2; `--strict-skip` also fails a SKIP). `--shard` with `--require-teeth` is refused (exit 2 before any suite runs, `# SENTINEL-SHARD-REQUIRE-TEETH-REFUSE`): the waiver gate judges the whole corpus and would report other shards' waivers as stale; run `--require-teeth` unsharded. Without `--shard` the runner is unchanged, and the local quiet-tree gate stays the unsharded run. In `.github/workflows/toolbelt-tests.yml` the join job keeps the name `toolbelt-tests` (what `merge-gate.sh` requires by default). Every edit to that workflow must refresh `research-sdd/toolbelt/tests/fixtures/merge-gate/wf-real-toolbelt-tests.yml` in the same commit (`cp`; byte-equality case in `merge-gate.test.sh`, reported `drifted` or `absent`; kit issue #2136). Each shard builds `rsdd` once for its own invocation (`rsdd:` aggregate line, see the Test suite row) and the shard job sets `RSDD_REQUIRE_GO=1`, so a failed build fails that shard. The shard job sets `RSDD_REQUIRE_BWRAP=1` / `RSDD_REQUIRE_NODE_TS=1` so suites that would SKIP for a missing sandbox / type stripping FAIL instead (kit issue #2138). The pi-hooks suites honour `RSDD_REQUIRE_NODE_TS` (PR #2137). |
| Teeth coverage | `bash research-sdd/toolbelt/tests/run-all.sh --require-teeth` | Exit 0 only when every `*.test.sh` suite runs mutation controls. Implies `--prove-teeth`; the aggregate prints, in this order and each on its own line, `Suites without teeth: N — [names]`, `(vocabulary check: a "teeth" case with no real mutant is a review item)`, `Suites n/a for teeth (node): N`, then — only when non-empty — `Suites with teeth but no banner: N — [names]`, then (always, an explicit `0 — []` when empty) `Suites with teeth not using lib/mutant.sh: N — [names]` (the teeth suites that never source `tests/lib/mutant.sh`, so their mutants carry none of its refusals: empty, byte-identical, syntax-broken, live-tree or symlink OUT — kit issue #943; the printed line is anchored in `run-all.sh` by `# SENTINEL-TEETH-HELPER-REPORT`, the detection by `# SENTINEL-TEETH-HELPER-LINT`); under `--prove-teeth` alone that line is report-only. Under `--require-teeth` it is a gate (kit issue #1299 item 4): four more lines follow it, in this order — `Suites with teeth not using lib/mutant.sh and not waived`, `Waived teeth-helper suites`, `Stale teeth-helper waivers` and `Invalid teeth-helper waiver lines` — and an unwaived suite, a stale waiver or an invalid line in `research-sdd/toolbelt/tests/teeth-helper-waivers.txt` (`<suite> <reason>` per line) exits 1. One further line, `Ambiguous teeth-helper suite names (both corpora): N — [names]` (kit PR #1569), follows those four: a hand-rolled suite basename present in BOTH corpora, so one waiver line could not be scoped to one file. It is report-only on its own (an unwaived ambiguous suite already fails via "not waived"); a waiver line naming an ambiguous basename is an Invalid line and fails. A waiver is debt to delete when the suite migrates, never a pass. The earlier `Suites without teeth` line is anchored in `run-all.sh` by the `# SENTINEL-NO-TEETH-BANNER` comment — cite the search term, never the line number, §8). Opt-in (kit issue #426): the default gate stays green while a suite that accepts the flag runs no mutation control — run it to see that debt, not to hide it. The live debt is whatever the printed `Suites without teeth` line names (no counts are recorded here). It implies `--tier all` (the stale-waiver check judges the whole corpus); an explicit `--tier core\|extras` with it exits 2 (`# SENTINEL-TIER-REQUIRE-TEETH-REFUSE`) |

**Where a new tool adds its registry entries (kit issue #2225).** Run-level NOTES go in a NEW file `research-sdd/toolbelt/reason-codes.d/<tool>.md`, and a NEW maint tool's row in a NEW file `research-sdd/toolbelt/tool-registry.d/<tool>.md` (each starting `### <tool>`), so concurrent PRs adding those merge in either order. The shared tables are still a conflict point and are deferred to a follow-up issue: the degraded/input `emitters` cells in `reason-codes.v1.md`, and the wrapper table in `tool-registry.md` that `tool-registry-discoverability` requires. `tests/registry-layout.test.sh` checks the integrity of the `.d` layout; it does not forbid appending to the main files.

**No suite or case counts are recorded here, deliberately.** For the current numbers, run the gate. Its
output is authoritative for that execution and that candidate — a later edit invalidates it, another
environment may not reproduce it, and the runner has its own blind spots. Do not persist those counts
here. This file used to carry a snapshot; when it was last checked it read 79 suites against 81 on
disk, and a case count the measurement had already moved past. Worse,
two local runs both reported 1,868 mutation cases while a separate verification pass in another context
reported 1,871. The cause was not established, and no per-suite log survived from the other run:
neither conditional coverage nor run-to-run variability could be confirmed or excluded. A figure that
careful measurements disagree on is not one a hand-written snapshot can promise to track. Doctrine
holds invariants and authoritative commands; live telemetry belongs to the instrument that produces it.

A writer that adds or edits any `.sh` file also runs the repo-wide lint suites
(`pipefail-sigpipe-lint.test.sh`, `lint-substitution.test.sh`, `self-dir-idiom.test.sh`) in addition to its
focused suites: these lints scan the shell tree (toolbelt, lib, install; `pipefail-sigpipe-lint` also
`tests/`), so any new or edited script, test or not, can fail them while its own suite is green (the full
gates of PRs #2131 and #2132 failed only on `pipefail-sigpipe-lint`).
Whenever a script emits or changes a typed state, it also runs `reason-codes.test.sh`: a new emitter of `absent-input`, `empty-input` or similar must be listed in `research-sdd/toolbelt/reason-codes.v1.md`, or that suite fails "real registry input rows vs real toolbelt" (PR #2140 full gate, 2026-10-11).

New suites dropped into `research-sdd/toolbelt/tests/` are picked up automatically — nothing to
register. Every suite must be able to print the exact run-all summary line `== N passed · M failed ==`
(any other format fails the full gate as "malformed summary"); `summary-line-lint.test.sh` checks that
statically across both corpora and names any suite without the emitter (a static floor, not proof of
runtime output; a suite whose summary is computed elsewhere declares `# summary-lint: dynamic <reason>`; kit issue #2169).

When scanning a suite log for failures, match the runner's own `  FAIL  ` prefix, not the bare string:
tests legitimately assert that things fail, so `FAIL` appears inside many PASSING lines. A bare grep
reports dozens of failures on a fully green run.

Every toolbelt script must have a companion `*.test.sh` under `research-sdd/toolbelt/tests/`.

**Spec acceptance scenarios must not carry bare literal counts.** A scenario may cite
`measured N on <YYYY-MM-DD> at <sha>` as a reference point; it must never use a bare N as an
assertion literal the gate compares against a live run. Live telemetry belongs to the instrument that
produces it; this extends the "no persisted counts" principle above to `openspec/**/spec.md` artifacts
— three-lane #8.

**A per-hook budget win that leaves the aggregate over budget is an unfalsifiable measurement.** The
SessionStart hook budget is output characters, not wall time (`openspec/specs/kit-session-cost/spec.md`:
under 8,000 characters total). State the aggregate character count, measure every registered hook
after each trim, and keep the aggregate in the instrument's own output. #437 (58bed7e) cut
`sweep-retros-hook.sh` from ~19,799 to 1,768 characters; the 7-hook aggregate still measured
8.7–9.4 k characters — over budget — closed by #504 — three-lane #4.

**A gate's calibration corpus must be a frozen fixture, not a live-fleet count.** A fleet count drawn
on the current day is a dated snapshot; the next commit moves it, and the gate then compares a stale
number against live output. Build a frozen fixture, commit it, and compare the gate's output against
that. The live-fleet reading is still taken, dated, and hand-verified alongside — it documents the
current state as a snapshot, but it is never the assertion the gate checks. Distinct from METHODOLOGY
§11b, which governs where the tooth bites; this governs what the gate compares against — three-lane #7.
