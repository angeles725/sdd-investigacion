# Blind-spot suites (kit issue #2201): suites whose reach into production code the word map in suite-impact.sh
# cannot follow (eval of built text, whole-kit copies/links, kit-wide globs, script names assembled at run time).
# They are added to a selection when a production CODE file changes, scoped by an optional reach (see below).
# Format: one `<suite> [reach=<glob>[,<glob>...]] <reason>` per line; <suite> is the file name without `.test.sh` / `.test.mjs`.
# REACH (kit issue #2201, part 1c) scopes a suite to the production files whose change it cannot see: it is added only
# when a changed code file matches a glob (repo-relative; bash `case` patterns where `*` crosses `/`; each glob starts
# with `research-sdd/`). A line without `reach=` is added for ANY production code change (the safe default for a suite
# whose reach is unknown). Derive a reach from what the suite copies, links or evals: a whole-kit copy of toolbelt/*.sh
# plus lib/ reaches those; a suite that mutates its own literal SUT and copies named libs reaches lib/ (its SUT is
# already a literal edge); a suite that only drives fixture copies of the test harness has no production reach but
# stays unscoped (it is also selected through the word map and the harness escalations); a python copier reaches
# toolbelt/*.py and lib/. A code change outside research-sdd/toolbelt/ adds EVERY blind-spot suite (no glob covers it).
# `--audit` flags a glob that matches no CODE file (tests/, install/, templates/ and Markdown never trigger the set).
# `suite-impact.sh --audit` re-derives the set from the corpus and FAILS (exit 1) for a detected suite missing here;
# a listed suite the detector no longer flags is kept on purpose (the detector is a heuristic, not a proof).
