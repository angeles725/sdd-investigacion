# gentle-ai SDD — Mental Model · Master Index

**Updated**: 2026-06-28 (Blocks 1-27 — full distillation of gentle-ai's SDD: philosophy + DAG + 10 phases + orchestration + persistence contracts + quality + multi-agent distribution + internal Go architecture)
**System analyzed**: gentle-ai (ecosystem configurator, Go binary v1.43.2) + its SDD layer (Spec-Driven Development) as materialized in Claude Code / OpenCode.
**Method**: Empirical READ-ONLY investigation with 7 sub-agents in parallel, contrasting the orchestrator contract (`~/.claude/CLAUDE.md`) against the canonical skills (`~/.config/opencode/skills/sdd-*/SKILL.md`), the agents (`~/.claude/agents/sdd-*.md`), the prompts (`~/.config/opencode/prompts/sdd/*.md`), the shared contracts (`_shared/`), the `gentle-ai` binary (verified via `--help`), and the source repository [Gentleman-Programming/gentle-ai](https://github.com/Gentleman-Programming/gentle-ai) (README + `docs/`). Replica of the `niagara-research` corpus style.

This index guides you through the **27 blocks** that document gentle-ai's SDD. Each block is an independent `.md` file that can be read in isolation, but the connections are explicitly marked between them with the form `[Block K]`. The autogenerated flat catalog lives in [CATALOG.md](CATALOG.md) (regenerate with `python3 tools/gen-catalog.py`).

## Certainty marker legend

The whole corpus uses the same epistemic honesty system as `niagara-research`:

- **`[CERT]`** = verified by reading the primary source, with a `path:line` or `path §section` citation.
- **`[CERT-a]`** = asserted by a source (README/docs/prompt) but **not re-verified** in its primary origin (e.g. Go code, or the binary's `--help`).
- **`[INFER]`** = author's deduction, not literal in the source.

## Cross-cutting findings (verified during the investigation)

These are the non-obvious discoveries that emerged when contrasting sources. They serve as a map of the **system's inconsistencies**, not as criticism — they document where the source of truth diverges:

1. **The ASCII DAG contradicts the dependencies table** `[CERT]` (B2). The diagram draws `design → specs`, but the phases table says `sdd-tasks` reads **spec + design** and `sdd-design` reads **proposal**. Operationally they are parallel branches from `proposal` that converge in `tasks`; the ASCII compresses that confluence.

2. **Vocabulary discrepancy in `status`** `[CERT]` (B4-B8). The agent prompts declare `done|blocked|partial`, but the common Return Envelope (`sdd-phase-common.md §D`) uses `success|partial|blocked`.

3. **The condensed prompts contradict their SKILL.md in `apply` and `verify`** `[CERT]` (B10-B11). The strongest case: `prompts/sdd/sdd-verify.md:33` says *"Do NOT run tests unless strict_tdd is active"*, the OPPOSITE of the SKILL.md (*"static analysis alone is never verification"*). The SKILL.md v3.0 + `references/report-format.md` is the canonical source. For tasks/archive/onboard the prompts are byte-identical to the SKILL.md.

4. **The native dispatcher does not expose `--help` per subcommand** `[CERT]` (B15). `gentle-ai sdd-status --help` fails with `unknown sdd-status argument "--help"`. The flags `--cwd`/`--json`/`--instructions` remain `[CERT-a]` (asserted in docs, not verifiable against the v1.43.2 binary).

5. **Hermes: `Detect-only` vs `Full`** `[CERT]` (B25). The README labels Hermes as `Detect-only`; `docs/agents.md` labels it `Full (delegate_task ephemeral)`. They are distinct axes `[INFER]`: `Detect-only` = installation mode; `Full` = runtime delegation mode. The README table lists 16 rows; Hermes is the 16th outside the 15 that the configurator installs automatically.

6. **opus ↔ Gatekeeper high-risk coincidence** `[CERT]` (B16, B18). The only two phases with the **opus** model (`sdd-propose`, `sdd-design`) are exactly the two high-risk phases that the Gatekeeper validates with a fresh reviewer. The model assignment is proportional to architectural risk.

7. **`docs/architecture.md` lists 8 Go adapters but the code registers 16** `[CERT]` (B27, resolved). `internal/agents/factory.go:defaultAgentIDs` registers **16 adapters** (claude, opencode, kilocode, gemini, cursor, vscode, codex, antigravity, windsurf, kimi, qwen, kiro, openclaw, pi, trae, hermes), each with `internal/agents/<pkg>/adapter.go` + test. The "8" in `docs/architecture.md` is doc debt (MVP snapshot); the "15" in the README is presentational (Hermes is the 16th row, detect-only). The authoritative count is **16**. Only 4 declare `SupportsSubAgents()==true`: Claude, Cursor, Kimi, Kiro.

8. **`state.json` is configurator state, not SDD state** `[CERT]` (B27). The `InstallState` struct (`internal/state/state.go`) persists `installed_agents`, per-agent/phase model assignments, `persona`, `last_update_check`, `pending_sync` — but does **NOT** persist SDD tasks/specs or scope/channel. The state of the SDD changes lives in the artifact backends ([Block 3]), not here.
