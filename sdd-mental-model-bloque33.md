# Block 33 — Adoption synthesis for the research-sdd kit: what to take, adapt or refuse from gentle-ai v4.0.0

Each row pairs the upstream evidence with what the kit does today (kit file cited), the proposed change, cost, value and the risk or doctrine conflict. > **SUBJECT VERSION**: gentle-ai v4.0.0 · tag sha `ff77164d` · 2026-10-01. Kit side: `origin/main` as present in the writing worktree on 2026-10-04.
> **SOURCES**: the upstream evidence of blocks 28-32; kit files named per row, read in this session: `.github/workflows/pr-check.yml`, `.github/PULL_REQUEST_TEMPLATE.md`, `research-sdd/toolbelt/{stage-retro-issues,reconcile-issues,state-update,retro-gate,research-sdd-status}.sh`, `research-sdd/install/research-sdd-install.sh`, `research-sdd/toolbelt/tests/`, `CLAUDE.md`.
> **METHOD**: ranking = value × evidence strength ÷ cost, doctrine fit as tie-break, and "incidence unmeasured" flagged per CLAUDE.md §7 ("a valid rule with zero observed occurrences is verifier discipline, not a work unit"). ## 33.1 — Verified kit finding: the issue-reference gate is blind to HTML comments `[CERT]`

`.github/workflows/pr-check.yml:24-26` (job Check Issue Reference) builds its verdict from `context.payload.pull_request.body` with `/(?:closes|fixes|resolves)\s+#(\d+)/gi` over the raw body; the approval job repeats the same regex at lines 49-51. Nothing strips HTML comments. `.github/PULL_REQUEST_TEMPLATE.md` carries instructional comments at lines 14-16 and the bare line `Closes #` at line 18. Today the bare template does not match (no number), so the defect is LATENT: a comment such as `<!-- Closes #N -->` left in the body, or pasted from a bot, satisfies BOTH gates, and a commented reference to any approved issue passes the approval gate too. gentle-ai closed the same hole in `.github/scripts/parse-linked-issues.cjs:38-47` (comments stripped to `-->` or end of input). Failure class: an instrument whose job is to refuse passes silently (CLAUDE.md §7). The verdict above is read from the regex, not from an executed repro; an executed repro is part of candidate 1's acceptance (RED against the current workflow script). See [Block 29] §29.8.

## 33.3 — Corrections to the sweeps' kit-side assumptions `[CERT]`

Found while verifying the table (kit files opened this session):

1. The communication sweep proposed expected-revision and atomic-write helpers on the premise that `state-update.sh` edits the envelope in place. It does not: `research-sdd/toolbelt/state-update.sh:2-5` states it is propose-never-apply and "NEVER writes to the target". The writer is `research-sdd-status.sh --sync-state`, which writes through a temp in the target's own directory followed by `mv` (an atomic same-filesystem rename, lines ~744-747 and ~995-1015). So candidate 19 shrinks from "no atomicity" to "no lock, no revision check, no fsync".
2. The issue-management sweep cited the kit gate regex at lines 21-23; the regex sits at lines 24-26 (and 49-51) of the workflow.
3. The issue-management sweep said `issue-creation` has no source in the upstream repo; it ships at `internal/assets/skills/issue-creation/SKILL.md` ([Block 30] §30.6). Candidate 9's "adjacent issues" field therefore has an upstream skill to imitate.
4. The upstream `odd/tasks` file count differs between the sweep (29) and a fresh listing (30); not material to any row.

## 33.4 — Do not adopt `[INFER]`

- **LLM-judged equivalence as the dedup key.** The upstream tracker shows at least four near-duplicate "granted START" reports ([Block 30] §30.8); the kit's deterministic signature is better.
- **Prompt-only issue creation.** The kit's doctrine is instruments as scripts with tests and mutation controls (CLAUDE.md §4, §7).
- **A multi-token consent envelope.** Propose-never-apply and GitHub approvals already carry consent.
- **The RDD default-on review ceremony (frozen candidate, acknowledge, burn).** It overlaps the kit's own adversarial review gate (CLAUDE.md §2) and conflicts with the quiet-tree authoritative gate run (§3); upstream itself marks the gates informational. Mine only the "normalize before review" idea (candidate 29).
- **The "Self-check BEFORE every response" / `paths-injected` self-report pattern.** Upstream records it as unverified (#1286); the kit's §7 would class it a self-reported PASS. Nor mass length as a technique: the kit's PROMPT-LOOP is the opposite direction, but trimming it is a separate measured unit.
- **Telemetry collector, Discord notifications, RC→stable promotion workflows, the `slop` label, the AI-assistance PR block, the agent builder, compile-time per-runtime adapters, the provider-contract archive.** No matching surface in a single-maintainer local kit.
- **The grandfather-exception schema as-is.** It fails upstream's own test "does it add a state, verb, flag, gate or parallel representation?" for a single-maintainer repo.
