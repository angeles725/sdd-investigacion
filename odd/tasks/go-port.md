# Feature: port the research-sdd toolbelt to Go (`rsdd`)

Status: planned · created 2026-10-19 · base `origin/main` 18b4b206 · owner: Project Manager session
Engram mirror: topic `odd/go-port/tasks` (project `sdd-investigacion`)
Epic: kit issue #2270. Supersedes the evaluation-only scope of kit issue #2202 (the maintainer authorised the full port on 2026-10-19).

## 1. Objective

Replace the production toolbelt (bash + Python + the small Node CLIs) with ONE modular Go binary, `rsdd`,
that behaves the same (byte-identical outputs and exit codes unless a divergence is declared with a
reason), runs faster, removes whole defect families by construction, and is quicker to change.

## 2. Why (measured, origin/main 18b4b206)

| Surface | Size | Pain it causes today |
|---|---|---|
| Production shell | 117 files, 35,750 lines | word-splitting, `set -e`/pipefail SIGPIPE races, ~182 `jq` call sites, GNU/BSD tool drift, >15 hand-copied GFM table readers held together only by a parity test |
| Production Python | 63 files, 21,588 lines | 7 copies of `renameat2` via ctypes, 7 canonical-JSON encoders, 8 `publish()`, 34 argparse CLIs, two import styles, 7 legacy adapters that never adopted `lib/adapter_core.py` |
| Tests | 211 suites, ~146k lines | 25–34 min single job (#2114), now 4 shards; dependency graph unknown to the runner (#2201) |
| Bash-only policing | ~4.9k lines of lints/guards | exists only because the code is bash (pipefail-sigpipe, lint-substitution, self-dir-idiom, lib-resolution, summary-line, mutant-syntax) |

The kit has almost no dead code (three audits agree): the win is unification, typing and speed,
not deletion.

## 3. Scope

IN: every production entry point under `research-sdd/toolbelt/` and `research-sdd/install/`
(117 shell + 63 Python + `adversarial-verify.mjs`, `adversarial-verdict.mjs`, `lib/session-budget-pi.mjs`,
`.github/scripts/parse-red-evidence.cjs`), their tests, CI, and the doctrine references to them.

STAYS in its own language (hard constraints, verified):
- `install/pi/research-sdd-hooks.ts` — pi/gentle-shell only load TypeScript extensions. It will call `rsdd`.
- `toolbelt/adversarial-verify.js` — Claude Workflow engine script; keeps a JS copy of the verdict kernel,
  held equal to the Go kernel by a parity test.
- `toolbelt/ghidra/*.java` (run inside Ghidra's JVM) and `toolbelt/jvm-callgraph` (SootUp is Java-only).
- `lib/ifc_driver.py` (ifcopenshell has no Go equivalent) and `lib/kaitai_driver.py` (generated Python
  parsers) — kept as sandboxed Python DRIVERS invoked by Go, exactly as today they are invoked by Python.
- Doctrine (METHODOLOGY, PROMPT-*, skills, profiles, agents) stays Markdown; only its command
  references change (phase 8).

OUT: target corpora (propose-never-apply), other repositories, niagara-*.

## 4. Architecture

### 4.1 Layout (mirrors the proven niagara-go conventions; no CLI framework)

```
research-sdd/rsdd/
  go.mod                      module github.com/angeles725/sdd-investigacion/research-sdd/rsdd (go 1.27)
  cmd/rsdd/main.go            one line: os.Exit(cli.Run(commands.Table, os.Args[1:], cli.OSStdio()))
  internal/cli                Main(args, Stdio) int; Stdio{In,Out,Err,Env,Clock,Cwd}; command table;
                              panic boundary -> typed degraded exit; usage/help generated from the table
  internal/commands           the registry: one entry per `rsdd <group> <cmd>` (name, flags, run func)
  internal/core/...           shared, dependency-free building blocks (see 4.2)
  internal/<domain>/...       one package per domain; a domain never imports another domain
  internal/testkit/golden     testdata/golden/<case>/{cmd.json,stdin,stdout,stderr,exit,intended.json}
  internal/testkit/parity     legacy-vs-Go differential runner (fixtures + read-only real corpora)
  internal/testkit/archtest   import-rule test (domain -> domain imports fail the build)
  Makefile                    check, test, lint (staticcheck pinned via `go run`), teeth (gremlins
                              pinned via `go run`), cross (CGO_ENABLED=0), parity, bench
  docs/adding-a-command.md
research-sdd/bin/rsdd         build output (gitignored)
research-sdd/toolbelt/lib/rsdd-exec.sh   the ONLY shim helper (resolve/build/degrade)
```

Adding a command = one file in its domain package + one registry line + one golden case directory.
That is the modularity contract, and `archtest` enforces it.

| `core/reasons` | `reason-codes.v1.md` table, generated by `go generate`; emitting a degraded line requires a `reasons.Code` value, so an unregistered code cannot compile (retires the regex in `reason-codes.test.sh`) |

| `core/fsx` | atomic write, `renameat2` NOREPLACE/EXCHANGE, `O_NOFOLLOW` safe open, fd sha256 (7+6+7+5 copies) |

### 4.4 Compatibility: strangler with shims

Callers are hooks (`.claude/settings.json`, the pi extension, `templates/hook-*`), CI, installed target
corpora that call `toolbelt/<name>.sh` through `hook-kit-run.sh`, and ~440 mentions in doctrine.
Therefore every ported path keeps a small shim until phase 8. The two canonical shim templates
(CLI and HOOK) live in the header of `toolbelt/lib/rsdd-exec.sh` and are executed verbatim by its
suite (symlinked, and with the lib absent), so a shim can never drift from them. Both resolve their own
directory with the RSDD-SELF-DIR idiom, not `$(dirname "$0")`, because hook shims are often invoked
through symlinks. CLI shims: a missing lib is `degraded` rc 2. HOOK shims: a missing lib is announced
with exit 0 (SENTINEL-HOOK-EMIT-GUARD), so the allow-on-degradation path always runs. Copy a template;
never hand-write a shim.

`rsdd-exec.sh` resolution: `$RSDD_BIN` -> `<kit>/bin/rsdd`. If a `*.go` file under `rsdd/` is newer
than the binary and `go` is on PATH, it rebuilds (`go build`, cached, ~1 s). If the binary is missing
and `go` is absent it emits the typed `degraded: rsdd-unavailable` line (hooks still exit 0 with a
DEGRADED headline) — never a silent pass (§7). Hook contracts preserved verbatim: sweeps exit 0 with
`additionalContext` JSON; gates read `{session_id,cwd,stop_hook_active[,transcript_path]}`, block with
`{"decision":"block","reason"}`, allow with exit 0 + empty stdout, report `branch=degraded` on stderr;
pkill guard answers `permissionDecision`; `return-token:` line verbatim (PROMPT-LOOP.md:1338).

### 4.5 Parity ("it must be the same") — four layers

1. **Existing suites as the black-box oracle.** A `.test.sh` that drives a script through its CLI keeps
   running unchanged against the shim; it must stay green in the same PR that ports the script.
2. **Differential runner** (`testkit/parity`): the legacy implementation (a pinned `origin/main`
   worktree) and `rsdd` run on every fixture and, read-only, on every real corpus on disk; stdout,
   stderr and exit must be byte-equal unless `intended.json` declares the divergence with a reason.
   This is the CLAUDE.md §7 "acceptance is a fleet sweep" rule, automated.
3. **Spec acceptance**: the 73 openspec scenarios and invariants INV-1..INV-5 become Go acceptance tests.
4. **Goldens** reused byte-for-byte: install plans x3, the 3 `json-envelope/default-output.golden` files (they pin
   the DEFAULT non-`--json` output, proving `--json` is a separate mode), verify-session-budget `_frozen` x11,
   lane fixtures x25, frozen retro/heading corpora, lint input/expectation pairs. No real `--json` envelope
   output was committed anywhere, so U0.2 adds envelope goldens generated from real `--json` runs of all
   four emitters (verify-registry, sweep-retros, retro-gate, resume-state — resume-state.sh:163-173 does
   emit a full envelope in `--json` mode) with a committed, hermetic regeneration script. Key order is
   per instrument (retro-gate and resume-state: schema,state,reason,counts,items; sweep-retros and
   verify-registry put counts before reason), so the renderer takes a per-instrument key order.

Suites that reach into Python/bash internals (69 run `python3` directly; `mutant_py_replace`) are
rewritten as Go tests in the same unit that ports their SUT. Teeth are kept: hand-written mutation
controls become table tests with a broken implementation injected through an interface, and
`make teeth` runs gremlins per changed package with a minimum efficacy gate. `lib/mutant.sh` and
`--prove-teeth` keep serving the remaining bash suites until phase 8.

### 4.6 Efficiency and caching

- One process instead of fork chains (bash -> jq/awk/sed/sha256sum/python3) on every hook.
- `rsdd hook session-start --all`: concurrent sweeps, one shared budget, one parse of TARGETS.md.
- Test speed: `go test` caches by compiler-known dependencies (what #2201 approximates for bash);
  CI runs `go test ./...` + the shrinking bash corpus; the shard count drops as suites migrate.
- A runtime parse cache (content-hashed, under `$XDG_CACHE_HOME/research-sdd/`) is NOT built by default:
  it is measured first (probe-viability rule, CLAUDE.md §6) after phase 2 and built only if the hot
  path still misses its budget.
- Targets (checked against Programador1's baseline, recorded in §9): SessionStart chain >= 5x faster,
  each hot-path command >= 3x faster, CI gate wall time <= 10 min by phase 8.

### 4.7 Errors and degraded states

Every command returns `(state.State, error)`; `cli.Run` maps it to the exit contract of
`json-envelope.v1.md:32-48` by default: 0 = any state except degraded (a finding is advisory and never
changes the exit code, CLAUDE.md §8), 1 = operational failure, 2 = usage error, 3 = degraded (missing
runtime dependency, `DEGRADED:` on stderr). Instruments whose legacy contract differs (e.g. verify-state
1 = stale, status 1 = no return-token) declare their own mapping in the command table, pinned by goldens.
Errors are wrapped with `%w` and carry the path/tool involved. A panic is recovered at the boundary and
is an operational failure: exit 1 with a typed `rsdd: internal-error` line — never exit 0, and never
labelled degraded (degraded means a missing dependency, not a bug).
Environment, clock and cwd are injected through `Stdio` (no `os.Getenv`/`time.Now` in packages), which
makes every test hermetic and parallel by default.

### 4.8 Distribution

`CGO_ENABLED=0` static builds for linux/darwin/windows x amd64/arm64. The installer builds from source
when `go` is present, otherwise downloads the release asset and verifies its sha256. Both harnesses
(Claude Code and pi/gentle-shell) keep working at every phase (hard constraint from #2202).
