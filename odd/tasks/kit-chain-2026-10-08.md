## Process lessons
- RDD `--base-ref` must be `git merge-base HEAD origin/main`; using a moving origin/main made RDD review the reverse of other merged PRs (false CRITICAL on #2004) and merge-gate refuse.
- A new lib sourced by verify-state.sh / research-sdd-status.sh must be added to every test kit with an explicit lib list (check-gap-drift, enforcement-e2e, research-sdd-archive); CI does not run --prove-teeth.
- CI shellcheck flags SC2218 (function redefined later in the file) that local shellcheck 0.11.0 misses.
- `gh pr edit` fails on the Projects-classic deprecation; use `gh api -X PATCH repos/{owner}/{repo}/pulls/N -F body=@file`.

- Speed (maintainer, 2026-10-09): writers run focused suites only; the orchestrator runs ONE full `run-all.sh -j 4 --prove-teeth` per PR head, serially; Opus review before the final gate; max 2 parallel writers; never `pkill` (a writer's pkill killed other gates).
- A count measured on an old base is stale after concurrent merges; re-measure on the merged tree.
- Changing how scripts locate themselves silently changes symlink-based fixtures and blinds lints that recognise the old idiom textually.
